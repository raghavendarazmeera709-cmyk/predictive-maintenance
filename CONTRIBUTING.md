# Contributing Guidelines

Thank you for contributing to the Predictive Maintenance and Process Intelligence project.

This project is developed as a collaborative team project. All team members are encouraged to contribute to development, testing, documentation, and improvement of the system.

## Contribution Process

To maintain a clean and organized development workflow, team members should follow these steps:

1. Create a separate branch for each feature, improvement, or bug fix.
2. Make the required changes in the branch.
3. Test the changes to ensure that existing functionality is not affected.
4. Commit the changes with a clear and meaningful commit message.
5. Push the branch to the GitLab repository.
6. Create a Merge Request describing the changes made.
7. Review the changes with the team before merging them into the `main` branch.

## Coding Guidelines

- Follow the existing project structure and coding style.
- Write clear, readable, and maintainable code.
- Use meaningful names for files, functions, variables, and classes.
- Avoid unnecessary changes to existing functionality.
- Test all changes before creating a Merge Request.

## Team Collaboration

- Communicate with team members before making major changes.
- Avoid working on the same files simultaneously when possible.
- Resolve merge conflicts carefully and verify the application after resolving them.
- Keep commit messages clear and descriptive.
- Review other team members' contributions when required.

## Security

Do not commit sensitive information such as:

- Passwords
- API keys
- Secret keys
- `.env` files containing credentials
- Private or confidential data

## Reporting Issues

If you find a bug or have an improvement suggestion, create an issue in the repository with a clear description of the problem and, if possible, steps to reproduce it.
